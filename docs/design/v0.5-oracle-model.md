# SEEP v0.5 design note: the oracle model

**Status:** experimental / preview. This describes the direction the v0.5 line
is taking and the reasoning behind it. The `scripts/ledger.py`,
`scripts/verify_gate.py`, and `scripts/run_falsification.py` modules are a
runnable first cut of the ideas below. Nothing here breaks the SEEP-0.4 message
or state protocol; the oracle core is additive.

## The problem with what SEEP does today

SEEP 0.4 has two AI models read the same evidence and exchange numbered
messages until they reach consensus, a documented deadlock, or a human
decision. Every check in that loop is one model evaluating another model's
claim, and both models receive identical inputs.

Two results from the multi-agent literature bear directly on this:

1. **Debate under identical inputs is a martingale.** Under a
   Dirichlet-Categorical belief model, two agents given the same evidence and
   allowed to debate show no expected improvement in correctness over rounds.
   The arguing, by itself, buys nothing.
2. **Convergence is where correlated error hides.** Models drawn from
   overlapping training data share priors, so they agree on wrong things.
   Weak models correct only a few percent of stance biases during debate and
   otherwise conform. Treating agreement as success rewards exactly the failure
   mode you most need to catch.

SEEP's own README already concedes the honest ceiling — "making shared blind
spots visible and expensive to maintain," not improving accuracy. But its
finish line still treats **consensus as a success condition**, which the second
result says is backwards.

## The organizing principle

The martingale is a statement about models exchanging *beliefs*. The escape is
not more agents or better debate — it is **putting oracles that are not models
into the loop.** A test that executes is not a belief. A hash that matches or
does not is not a belief. A citation that resolves to the claimed bytes or does
not is not a belief. The moment a non-model oracle decides a step, correctness
gets an anchor outside the models' shared priors, and the martingale no longer
applies to that step.

So grade every mechanism SEEP has by one axis — does a model decide it, or does
an oracle?

| Mechanism | Decided by | Verdict |
|---|---|---|
| Citation verification (sha256 vs evidence) | oracle | keep — this is the good part |
| Red-green falsification gate | oracle | **add — the missing half** |
| Coverage accounting | partly oracle (filesystem access is checkable) | strengthen with real evidence |
| Agree / disagree / consensus debate | model-to-model | **demote to a signal, not a terminal** |

The whole v0.5 thesis is one line: **maximize non-model oracles, minimize
model-to-model adjudication.**

## Three terminal states, not consensus

`agree / disagree / partially_agree / unresolved` and the "consensus" finish
line are replaced by a claim lifecycle with three terminals:

- **promoted** — survived falsification. A red-green record proves it.
- **killed** — disproven by an oracle, or the bug was never reproduced.
- **unresolved** — could not be reduced to an oracle-decidable check; escalate
  to a human.

`open` is the only non-terminal state. Agreement between models is not a state
at all. It may *inform* who writes the falsifying test, but it never promotes a
claim. See `examples/oracle-core/ledger.jsonl` for all three terminals in one
worked exchange.

## The promote gate: red before green

A claim advances to `promoted` only when a falsification record shows the
assertion **fails on the buggy tree (red)** and **passes on the fixed tree
(green)**, and was actually executed. This does more work than the entire
two-model structure:

- It kills speculative findings. "This looks fragile" cannot be expressed as a
  failing assertion, so it routes to `unresolved`, never `promoted`.
- It resolves disputes without another debate round. Someone writes the
  assertion; both trees run it; the exit codes decide.
- It directly targets the failure this project exists for. A silent wrong
  p-value has, by definition, an assertion that distinguishes right from wrong.
  If you cannot write that assertion, you do not yet understand the bug.

`run_falsification.py` runs a repro command against a base tree and a fix tree
and emits a `falsification_recorded` event; `ledger.py`'s gate refuses to
promote without one that is genuinely red-then-green.

## Rule 8, extended to concessions

SEEP core rule 8 already says "agreement without primary evidence remains
unresolved." Today it guards *initial* agreement. v0.5 points it at
*concessions*: when an agent changes position toward agreement, the concession
is valid only if it cites **new evidence the original claim did not carry**. A
bare "you're right, I agree" is capitulation, and the ledger rejects it.

This is oracle-checkable (does the cited evidence exist, and is it new?) and so
it is a better instrument than a concession-rate threshold. It is **necessary,
not sufficient** — a model can still manufacture the evidence it then cites, so
the concession rule reduces sycophantic convergence without claiming to
eliminate it.

## One agent now, two agents later — as a hypothesis, not a premise

The naive two-agent design (a second model as *corroborator*) is what the
martingale demolishes. There is a different, defensible role: a second model as
**adversary against the oracle**, not against the first model. The finder
reduces a claim to a failing test; the other agent writes the fix **without
seeing the finder's proposed fix, only the red test.** If the fixer reaches
green by a different diff, that is real corroboration arbitrated by execution,
not agreement.

But a second agent only pays for itself if its isolation is real, and enforced
isolation is expensive (separate clones at minimum — never git worktrees, which
share one `.git` and leak the exchange; separate OS users or containers if the
result is to be published). So v0.5 is deliberately sequenced:

- **v1 (now): one agent + falsifiability gate + verified citations.** No
  isolation problem. This is the oracle core in `scripts/`.
- **v2 (roadmap): the adversarial second agent**, finder-writes-test /
  other-writes-fix, added only after the one-agent version has been shown to
  catch something a single pass misses.

The number of agents is left as a **hypothesis with a test attached**, not
declared. The MoSeq run below decides it: run v1, count findings that survive
the gate; then run v2 on the same forks and measure whether the adversarial
fixer kills findings v1 accepted. If it kills a meaningful fraction, two agents
is proven. If it kills nothing, two agents is ceremony — learned cheaply.

## The acceptance test: earn it on MoSeq

SEEP has schemas, four releases, and zero adopters. This design does not earn
credibility from being well-specified; it earns it from a result. The concrete
test:

> Run the oracle core against the five MoSeq2 forks (upstream = base tree, fork
> = fix tree). **Does an oracle-gated review promote at least one finding — a
> real numerical defect — that a single unstructured review pass missed?**

If yes, SEEP is justified and the caught bug is the artifact. If no, SEEP's real
value is thinner than hoped, which is worth knowing cheaply and worth
publishing honestly. Either outcome beats another schema version.

## Honest relationship to prior art

The individual pieces are mature and this note claims no primitive as novel:

- **Red-before-green** is TDD / regression testing.
- **A verified, append-only claim ledger** is close kin to `in-toto` / SLSA
  attestation (verified provenance of steps) plus event sourcing.
- **Executable scorers that gate on assertions** exist in LLM-eval harnesses.
- **The adversarial multi-agent method** (context asymmetry, kill mandates,
  banning convergence-by-debate, a single empirical test as the decisive tool)
  is described retrospectively in security-research practice, not as a reusable
  tool.

What does not exist as a named, substrate-neutral thing is the *composition*:
a portable claim ledger whose promotion gate is a falsification oracle, whose
citations resolve to real bytes, and which treats convergence as suspect rather
than as success. That novelty is thin, and thin novelty is fine — but only if
it produces the MoSeq result above. The composition is the bet; the result is
what settles it.

## What this demotes

The directional message folders, the numbered-message ceremony, and the
consensus finish line are the parts most likely to be redundant with existing
orchestrators, and they are not where the oracle value lives. v0.5 does not
delete them yet — it stops treating them as the core. The
`10_EXCHANGE/`-folder-collapse question, previously the v0.5 headline, is a
deck chair next to the question of whether an oracle-gated review catches a real
bug. It is deferred, not scheduled.
